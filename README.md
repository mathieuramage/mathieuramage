# Mathieu Ramage

I build agentic software delivery systems, operational SaaS products, and practical tools that turn messy workflows into governed, observable execution.

Most of my current work is product-side and private, so this profile is the public map of what I am building and where I am strongest.

## Current Focus

- **SlashCommand** - governed agentic delivery for GitHub: backlog governance, PR automation, policy gates, human-in-the-loop approvals, and audit-ready execution.
- **BetterGrid** - a field-work operating system for infrastructure teams, with maps, RBAC, compliance workflows, offline-oriented UX, and Supabase-backed operations.
- **CityLens** - local event intelligence on a map, combining public and partner signals such as RSS, open data, press, Waze-style incidents, and social sources.
- **Handler V2** - handle-addressed messaging from the email client people already use, starting with a clean protocol and Gmail-first prototype path.
- **FireFly** - embedded CAN/OBD exploration for authorized vehicle visibility use cases, with firmware, sniffing tools, and safety-first validation.

## Strongest Areas

- **TypeScript product engineering**: Next.js, React, Vite, Node.js, API routes, monorepos, typed contracts, and pragmatic frontend architecture.
- **Agentic systems and GitHub automation**: GitHub Apps, Octokit, CI watchers, PR orchestration, merge governance, policy gates, and evidence trails.
- **Cloud-native operations**: Google Cloud Run, Cloud Run Jobs, Firestore, Secret Manager, Cloud Scheduler, Cloud Tasks, Supabase, PostgreSQL, and deployment runbooks.
- **Product systems**: turning rough ideas into structured scopes, governance rules, workflows, docs, tests, and usable interfaces.
- **Verification discipline**: Vitest, Playwright, lint/typecheck pipelines, smoke tests, security checks, accessibility checks, and rollback-oriented delivery.

## How I Work

I like products that are operationally real: clear constraints, explicit safety rails, strong docs, testable decisions, and interfaces that help people act without guessing.

My default mode is to connect product strategy, engineering architecture, and delivery mechanics in the same loop: define the system, build the useful slice, verify the behavior, then harden the path so it can run again.
